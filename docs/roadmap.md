# Data Governance Lab roadmap

Status: working plan · 2026-09-25

## M1 — Playable reference case (in review)

Deliver [Case 01](../cases/01-two-numbers/PLAY.md) with a fixed world, seven discoverable artifacts, four stakeholders, executive challenges, a five-dimension rubric, and clear play instructions. Verify a complete run from kickoff to feedback. This is the invariant reference for future generated cases.

## M2 — Solo validation and blind-spot review (in progress)

The author is continuing without external testers for now. Record observed failures from personal runs and self-review. The two Case 01 playthroughs exposed premature clue release and an unfair penalty for an unavailable fact; both were revised. The generated-case prompt, case schema, regulatory relevance gate, and learning-goal menu now exist in draft. Test them with at least one regulatory and one non-regulatory generated case, and check solvability, role authority, source handling, and arithmetic. This does not establish reliability across combinations.

## M2b — Unaided pilot (deferred)

Run five to ten complete sessions with new learners using their own AI chat access. Track duration, completion, contradictions, evidence retrieval, premature disclosures, stakeholder boundary violations, and usefulness of feedback. Resolve failures and revise Case 01. Exit gate: at least four of five complete without author intervention, and at least four identify a specific useful improvement in their feedback. These are product pilot targets.

## M3 — Second authored case and schema

Write a second case in another industry or governance capability. Extract a versioned case schema: public brief; quantitative invariants; actors and knowledge boundaries; evidence IDs and unlock conditions; private causal model; constraints; assessment anchors. Add a validator or manual checklist that rejects missing evidence paths, inconsistent arithmetic, and impossible investigation. Confirm the facilitator can run either case without modifying its core instructions.

## M4 — Player choices

Add difficulty first (complexity of conflicting incentives, ambiguity, and decisions), then focus area and industry. Each industry guide should cover typical processes, roles, data objects, and tensions. Keep country-specific rules in separately dated and cited references; avoid presenting generated legal claims as current fact. Generate one full case bible at kickoff and keep its facts fixed during play. Pilot complete runs in every newly supported option.

## M5 — Skills-only plugin

Package facilitator workflow, case schema, and vetted cases as a skills-only plugin. Test availability and installation in the intended users' ChatGPT environments. Public submission requires verified publisher identity and review materials; the plugin can avoid project-hosted API and MCP infrastructure. Preserve a downloadable prompt/case pack for portability.

## M6 — Decide if stronger infrastructure is justified

Only add a server or web application if observed pilot failures require durable progress, controlled hidden state, secure assessment, or a visual evidence workspace. Estimate cost per completed session from real measurements before choosing a hosted model.

## Quality principles

Business problem before governance terminology. Discovery before recommendation. Fixed causal facts during play. Stakeholders know only their own facts. Multiple defensible recommendations can score well. Feedback cites what the learner actually did. Scores are formative unless a separately validated assessment is developed.
